# 商品视觉设计规则

## 生成器结构（参考 assets/example-demo/build.py）

- 顶部是数据：`MEMBERS` / `PACKS` 等列表，每个商品一个 dict（id、展示名、短名、月数、次数、角标、色调、页脚文案……）。文案改动只改这里。
- 样式分三层：`BASE_CSS`（颜色 token、品牌标、徽章、渐变文字、进度条）→ `MAIN_CSS`（主图）→ `DETAIL_CSS`（详情）。
- 函数分工：`main_xxx(item)` 返回主图 HTML，`detail_xxx(item)` 返回详情 HTML，`build()` 循环渲染。
- 渲染用 `scripts/render_tools.py` 的 `shoot()`、`trim_bottom()`、`slice_long()`、`overview()`。
- 输出目录：`主图/`、`详情页/`、`详情页切片/`、`html/`（源码）、`主图总览.png`。

## 版式经验

- 主图（800 画布）：顶栏（品牌 + 角标）→ 主视觉（卡面或插画，约 340 高）→ 三个数据块 → 底部一行说明。数据块里写可以公开的硬指标（有效期、次数），不写价格。
- 同一系列靠一处视觉差异区分档位，不要每张都换布局。
- 详情页首屏左文右图：文字列宽控制在 400px 以内，右边装饰卡斜放、贴右边。中文标题超过 6 个字就换行，别让文字伸到装饰卡底下。
- 详情页每节是白底圆角卡片 + 左侧橙色竖条标题；对比表把当前商品那一行高亮。
- 「怎么开通」固定 3 步：下单填写手机号 → 支付成功到账 → 打开 App 查看，再加一个虚线框强调留言填写。
- 长图切片：每段不超过 3400px（2 倍图），保持原宽；上传到详情时按顺序传，买家看到的是无缝长图。

## 文案与合规

- 用业务方的「对外标准口径」原文改写，不要自己编权益。
- 禁用：最划算/最优惠/第一/无限 xx；对虚拟服务写「虚拟权益」（改说「App 会员服务」）；业务方不公开的数字。
- 角标只用业务方允许的词（例：「推荐」「新人专享」「会员专享」）。
- 购买须知要写：无需物流、到账即可使用、不支持七天无理由、一单只对应一个账号、填错号码联系客服退款重下、账号注销后权益作废。

## 不公开数字时的替代方案

三段式进度条，和 App 状态条视觉一致：

```css
.meter{display:flex;gap:6px;justify-content:center}
.meter i{border-radius:999px;background:#F3E6DC}
.meter i.on:nth-child(1){background:linear-gradient(90deg,#FFCB94,#FFAE70)}
.meter i.on:nth-child(2){background:linear-gradient(90deg,#FFAE70,#FF8C48)}
.meter i.on:nth-child(3){background:linear-gradient(90deg,#FF8C48,#FF6B24)}
```

满格表示「每月满额发放」，亮 1/2/3 段表示小/中/大。卖点文字同步改成「每月发放 AI 权益」「含 AI 权益补充」。

## 自查清单（每次渲染后）

- [ ] 标题、副标题、按钮互不遮挡，没有装饰元素压在文字上
- [ ] 没有一两个字单独折行
- [ ] 圆角图没有露出黑色渲染底色（需要圆角时让容器负责，或给 html 设页面底色）
- [ ] `grep` 扫 HTML：没有残留禁用词或禁用数字
- [ ] 总览图里同系列的视觉一致
- [ ] 价格没有出现在图里
